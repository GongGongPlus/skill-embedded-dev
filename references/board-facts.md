# 板级事实：从网表与配置提取引脚映射

适用场景：没有原理图标注、只有 PCB 工程或 .ioc/ioc 文件时，回答"这个信号接在哪个引脚""这个引脚复用了什么外设""主控是哪一个"。原则：**板级事实只能来自可核对的一手文件；推断必须标注证据等级，歧义必须停下**。

## 一、支持与拒绝的输入

- 支持：KiCad XML 网表（`export` 根，含 `components` 与 `nets`）、CubeMX `.ioc`。
- 明确拒绝而不是猜：普通 PDF、扫描件、Altium Smart PDF 之外的 PDF、无法解析为 XML 的文件、没有主控候选的网表。
- Altium/OrCAD .NET 网表可解析连接，但常常没有引脚名；没有引脚名时只能给网络与位号，不得编造 pin_name。
- 非 `export` 根或 XML 解析失败 → 退出码 6（配置错误），并说明缺什么。

## 二、主控识别

1. 先按位号前缀分类元件：`U/IC/A` 为 IC，`R/L/C/FB/FL/F` 为无源件，`C` 可能同时是电容，`Y/X/XT/OSC` 为晶振，`J/CON/CN/P` 为连接器，`D` 为二极管，`SW/S` 为开关，`SB/JP/LK` 为桥接/跳线，`TP` 为测试点，`NT` 为网络连接点。
2. 候选评分：`pin_count + 40（IC）+ 50（型号/描述看起来像 MCU）`。得分最高者为主控候选。
3. 若两个候选都是"像 MCU"且分差小于 15：**判定为歧义，退出码 4，列出候选与分数**，要求显式 `--main-controller REF`；不擅自选。
4. 强制指定位号必须存在且属于 IC 类；选择连接器或无源件直接报错。
5. 主控的电源/地引脚（`power_in/power_out` 或网名为 GND/VDD/3V3 等）从信号引脚表中排除；它们不是外设连接。

## 三、引脚追踪规则

每个信号引脚输出：`pin / pin_name / net / direct_nodes[同网全部节点] / traced[逐条路径]`。

- `direct_nodes`：直接同网的元件引脚（含连接器、去耦电容）。
- `traced`：穿过串联无源件到达的端点。串联 `R/L/FB/FL/F` 一律穿过；`C` 只有在两端网络都是信号网时才穿过（去耦电容的另一端通常在电源/地，因此只出现在 `direct_nodes`）。
- 路径终点：非通过中间件的元件引脚（`endpoint`），或落到电源/地网络（`endpoint:null, rail:"power"|"ground"`）。
- 未贴装（DNP/DNF/N.C.、`populate=no`）的元件仍然报告，但必须标记 `dnf`；不能当成已连接。
- 追踪深度 ≤4，避免通过大网络无限扩散；路径中不得把中间件自身引脚当作终点（例如经过 R1 后终点不能又是 R1）。
- 连接器节点保留连接器位号与引脚号，这通常是"外部线束接到哪里"的答案。

## 四、CubeMX .ioc 解析

- MCU 名称优先级：`Mcu.UserName` → `Mcu.Name` → `Mcu.PartNumber`；只有 UserName 缺失才回退，不要把同一芯片的多种写法当成多个候选。
- 提取：`Mcu.Family`、`Mcu.Package`、外设清单 `Mcu.IPn`、引脚 `P*.Signal/Mode/GPIO_Label`。
- 引脚风险提示（只提示，不替代核对）：PA13/PA14 默认 SWD（禁用作 GPIO 会失去调试口）；PB3/PB4/PB2 受 JTAG/BOOT 影响；PC13/PC14/PC15 驱动能力弱或与 32 kHz 晶振共用；BOOT0 影响启动模式。
- 风险提示写进输出，不静默过滤；需要用户/数据手册确认。

## 五、证据与结论范围

- 网表给出的是**设计声明**：引脚映射不代表固件真的这样配置。要证明固件行为，必须读固件配置或真机观测。
- 报告必须写清来源文件与格式（KiCad XML 版本、.ioc 版本）。跨版本解析差异不能靠猜补齐。
- 结论强度不超过证据强度：只有网表 → 说"设计上连接"；有固件配置 → 说"软件配置为"；有真机寄存器/逻辑分析仪 → 才说"实际输出"。
- 发现网表与 .ioc 冲突时停下，列出冲突点，让用户确认以哪份为准；不要自行二选一。

## 六、与真机排查的衔接

得到引脚图后，下一步才是外设 bring-up：时钟/复用是否正确、GPIO 模式、上下拉、开漏、DMA 通道与对齐、时序与电气。引脚对了不代表外设能通；硬件事实（网表/手册）与现场证据（示波器/逻辑分析仪/日志）要分别标注。
