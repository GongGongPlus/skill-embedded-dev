# 证据范围与结论边界

适用场景：任何要下"修好了""通了""稳定了""已烧录"结论的场合。规则：**结论的范围不得超过证据覆盖的范围；没有观测到的东西不能写成观测到了**。

## 一、四类证据，不可混用

1. **配置/声明**：.ioc、时钟树、引脚分配、链接脚本、库版本。证明的是"设计/配置如此"，不证明实际运行如此。
2. **软件自报**：日志、寄存器打印、`HAL_OK`、驱动返回值。证明软件认为自己做了什么，不证明物理层真的发生。
3. **推导量**：根据配置或理论算出的数值（波特率误差、采样率、理论吞吐）。必须标注"推导"，并给出公式与输入。
4. **直接观测**：示波器/逻辑分析仪波形、真实串口字节、烧录器回读、调试器读到的 PC/CFSR。这是最高等级证据，也要写清测量条件与设备。

把 3 或 4 写成 1，或把 1 写成 4，是最常见的幻觉来源。

## 二、结论与证据对齐

| 结论 | 需要的最小证据 |
| --- | --- |
| 代码编译通过 | 构建命令真实退出码 0 与产物路径 |
| 固件已烧录 | 烧录器/OpenOCD 等工具的烧录步骤成功，且镜像标识/校验和与构建产物一致 |
| 目标在运行 | SWD 读到的 PC/SP 在合法范围，或串口有预期输出（附原始字节） |
| 外设真的工作 | 引脚波形/总线解码/对端设备响应，三者至少其一为直接观测 |
| 测试通过 | 测试命令退出码、用例数、失败清单；测试通过不等于硬件验收 |
| 调试结论成立 | 故障寄存器/栈回溯/日志证据 + 能解释现象的机制 + 可复现步骤 |

"编译成功"不等于"已烧录"；"烧录成功"不等于"运行正确"；"串口有输出"不等于"协议正确"；"参数写回 0"不等于"寄存器实际生效"。

## 三、常见越界模式（行为回归用例的判据）

- 把仿真/估算的运动说成观测到的运动（`estimated-motion` vs `observed-motion`）。
- 没有烧录证据就说"已修复并验证"（`flash-evidence`）。
- 拿旧构建的日志证明新镜像（`stale-firmware`）。
- 用工程外的 SDK/头文件路径构建，却给出项目结论（`sdk-outside-path`）。
- 两个探针/会话同时占用调试器，用户以为在线（`probe-owner`）。
- 日志为空时把"无输出"解释成"通过"（`empty-log`）。
- 没有数据手册就给出寄存器级结论（`missing-datasheet`）。
- 配置与观测冲突时挑一个报告（`conflicting-observation`）。
- 把通信"配置了"说成"通信已验证"（`verified-communication`）。
- 用名义采样率代替实际 ADC 采样率（`adc-actual-rate`）。
- GPIO 锁存/输出寄存器写了就认为引脚电平已变（`gpio-latch`）。
- 请求已排队/已发送就认为已被对端接收（`queued-not-delivered`）。

判据是**明确的字段值与必要的观察动作**，不是命令逐字匹配；评价不看措辞是否漂亮，只看结论是否与证据同域。

## 四、HIL 诊断报告契约

`embedded_dev.py hil` 产出的 `diagnostic_report.json` 必须包含：`schema_version`、`iteration`、`project`、`status`、`summary`、`signature`、`next_actions`、`ai_repair_prompt`、`repeated_failure`、`source_unchanged`，以及编译错误、串口尾部与时间戳等上下文。

- `status` 枚举：TEST_PASSED / BUILD_FAILED / FLASH_FAILED / HARD_FAULT / ASSERTION_FAILED / TEST_FAILED / TIMEOUT / SERIAL_UNAVAILABLE / STALLED。
- 同一失败签名（状态+故障位+日志尾部）重复出现，并且源码未变、HEAD 未变：判为 `STALLED`，停止重试并请人介入，而不是继续换参数碰运气。
- 退出码与状态一一对应：0 通过、1 构建失败、2 烧录失败、3 目标故障、4 测试/串口/超时、5 停滞、6 配置错误。
- 报告里的 `ai_repair_prompt` 是给下一轮的最小上下文，不是修复保证；`next_actions` 必须可执行（命令/读哪个寄存器/看哪份手册）。

## 五、证据分级（与完成报告同口径）

- 已确认：有直接观测/官方手册/可复现实验支撑，注明来源。
- 工程推论：由已知事实推出，写清推理链。
- 估算：有数量级与假设，给出误差范围。
- 待验证：需要实验或读手册才能确定，列出验证方法。
- 数据不足：明确缺什么，不硬给结论。

完成报告必须逐条标注证据等级；跳过项、未验证项和风险与结论同等显眼，不藏在末尾一句"可能存在风险"。

## 六、停止条件

证据无法获得、设备被占用、连续无进展、观测与配置冲突且无法判定、需要拆机/接强电等不可逆高风险操作时：停止并请求用户决策。继续猜命令或继续"修一点再看"比停下更贵。
