# 外设 Bring-up 与调试

## 通用顺序（不要跳步）

1. 硬件层：供电电压、共地、走线、上拉、电平匹配（3.3V/5V/1.8V）
2. Pin mux / 电气模式（复用功能、开漏/推挽、上下拉）
3. 外设时钟使能 + 复位释放（**访问外设寄存器前必须先开时钟**）
4. 最简可观察动作：翻转 GPIO / 发 1 字节 / 发 1 次 burst / I2C 扫址
5. 轮询验证通过后才上 IRQ / DMA
6. 逻辑分析仪/示波器对照测量——**仪器是最终裁判**，"看起来对"不算数

单总线失败先降速（如 SPI 20MHz→10MHz）隔离时序问题，再逐步提速。

## UART

- TX/RX **交叉**连接；必须共地；确认电平
- 乱码第一嫌疑是**时钟源**（外设挂在哪条总线、主频是否如预期），其次才是波特率数值；查 BRR/分频计算
- 默认 115200-8N1-无流控；两端配置逐位核对
- 抓启动日志必须**先开终端再复位**
- 症状速查：完全无输出→TX 线/共地/错 UART 实例/复位时机；bootloader 后中断→app 跳转后外设未重初始化/中断向量未重定位；复位瞬间随机字符→boot ROM 波特率不同（正常）

## I2C

- 空闲时 SDA/SCL 都应为高；无上拉或上拉过大（建议 4.7kΩ，按速率与电容调整）是最常见硬件问题
- 地址分 7-bit/8-bit 表示；扫址范围 0x08–0x77；先看 ACK 再谈数据
- 总线卡死低电平：设备锁死（常有），可用 9 个 SCL 脉冲 + STOP 解锁；软件上加重试与总线恢复逻辑
- 先查数据手册的寄存器写序（有些器件要求先写寄存器地址、有些支持 auto-increment）

## SPI

- CPOL/CPHA 四种模式按器件手册定，**不要试错式乱调**；用 `0xAA 0x55 0xF0 0x0F` 测试向量验证位序/极性
- CS 空闲态、建立/保持时间；高速时注意 pre/post delay
- MISO/MOSI 接反的典型症状：读到的全是 0x00 或 0xFF
- 多从机时每器件独立 CS；注意菊花链器件与共享总线的吞吐

## ADC

- 先校准（STM32 出厂校准读取 / ESP32 `adc_cali`）再做测量
- 采样时间 vs 信号源阻抗：高阻源需要更长采样时间或加跟随器
- 多次采样均值/中值滤波；ESP32 注意 attenuation 决定量程——**量程以 datasheet 的 attenuation 表为准，勿凭记忆写数值**
- 参考电压是否稳定直接决定精度

## DMA

- 先证明轮询/中断路径可用，再开 DMA（分两层归因）
- 缓冲区对齐要求（按手册，常 4 字节）；**cache 系统必须做 cache 维护或把 DMA 缓冲放在非 cache 区**（M7/PSRAM 高频坑；由此产生的不精确总线错误见 fault-debug.md 的 IMPRECISERR 行）
- ESP32 SPI DMA 单次传输限制（经典 ESP32 ≤4092 字节，S3 32KB），超限分块
- DMA 写目标的生命周期必须长于传输——静态分配最安全；检查长度字段与实际缓冲大小一致（溢出写 = 运行后随机 HardFault，归因路线见 fault-debug.md 根因清单）

## CAN

- 位时序（采样点 75–87.5%）、波特率两端一致、终端电阻 120Ω×2
- 无 ACK → 总线上无其他节点/未加终端；error passive/blink 状态先看 ESR
- 过滤器配置错收不到帧；先全收模式验证物理层，再收紧过滤器

## LCD/传感器类

- LCD：用整屏红/绿/蓝填充分辨初始化序、窗口地址、RGB/BGR 位序问题；"GUI 看着没问题"必须拍照对比，不允许目测通过
- 传感器：先读 WHO_AM_I/芯片 ID 验证总线与地址，再谈数据正确性
- 移植厂商示例：只提取最小模式，剔除 demo 凭据/端点；先在目标板跑通一个最小端到端场景再扩展
