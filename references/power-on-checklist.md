# 上电即跑自检（烧录/交付前必过）

**第一步该做什么**：烧录前跑七维自检；任何一维不满足 = 不得声称"上电即可运行"。

## 七维上电自检（竞赛/量产交付前逐项核验）

| 维度 | 检查项 | 失败特征 |
|---|---|---|
| 1. 入口调度 | 向量表 word1 指向 Reset_Handler；main 前 `.data` 拷贝与 `.bss` 清零完成 | 复位循环、无输出 |
| 2. 时钟配置 | 系统时钟/外设时钟在对应外设访问前已使能 | 外设区 BFAR 故障（见 fault-debug.md） |
| 3. 通信链路 | CAN/串口/SPI 波特率与对端规格一致；收发引脚复用正确 | 通讯无响应、乱码 |
| 4. 中断/DMA | 使能的中断都有 ISR；DMA 缓冲对齐且不越界 | 假死、随机 HardFault |
| 5. 任务逻辑 | RTOS 任务栈/堆预算充足；无空转任务抢占 CPU | 任务创建失败、死锁 |
| 6. FPU | 编译开启 FPU 的核已使能 CPACR | 立即 HardFault |
| 7. 编译/链接 | 干净构建零错误；无重复符号；map 文件核对 ZI/RW 在 RAM 预算内 | 链接失败或运行期内存踩踏 |

## 堆余量铁律（任务创建失败死锁）

**实测教训（2026R1H7 底盘，已确认）**：`configTOTAL_HEAP_SIZE = 15360B` 余量不足——任务创建在启动期失败后无人处理，表现为"上电后系统静默死锁"。提到 32768B 后 ZI=54484B 仍在 128KB IRAM 预算内，问题消失。

规则：
- **堆预算 = 理论需求 × 1.5 起步**，再用 `heap_4` 的 `xPortGetFreeHeapSize()` 实测余量收尾
- 编译后用 map 文件核对 ZI/RW 总量 vs RAM 预算，差值必须大于预估任务栈总和
- 任务创建必须检查返回值：`pdPASS` 才继续，失败进显式错误路径（LED 快闪/日志），禁止静默继续
- 没有分配失败 hook（`vApplicationMallocFailedHook`）+ 栈溢出 hook = 风险未暴露，不声称稳定

## 重复符号链接风险

**实测教训（已确认）**：仓库里同时存在未编译的 `bsp_fdcan.c/h` 与在用的 `bsp_can.c`——一旦两个文件都被加入构建，链接期重复符号直接失败；若其中一个"恰好没被编译"，则风险潜伏到某次构建配置变化才爆发。

规则：
- 废弃/未启用的驱动文件**要么删、要么标记 `deprecated` 并从构建排除**，禁止"先留着"
- 交付前构建清单（Makefile/CMake/CubeMX 源文件列表）人工过一遍：同一外设只允许一个驱动源文件在编

## 外部数据源缺失 = 功能静默失效

**实测教训（已确认）**：`CHASSIS_POS_SOURCE = POS_SOURCE_NONE` 时，`pos_valid` 恒为 0——自动寻路/取杆功能"看着在跑、实际永不执行"，且没有任何报错。

规则：
- 每个依赖外部输入（IMU/ODOM/测距/标定坐标）的功能，必须有**显式的数据有效性标志链**：源 → 有效位 → 功能门控
- 功能不执行时先查"数据源是否被配置为 NONE/未标定"，再查算法逻辑
- 上线前对着功能清单逐项确认"此功能依赖哪个数据源、当前是否配置正确"，不要默认全开

## 如何证明"上电即可运行"

① 七维逐项列出证据（配置截图/代码行/构建输出）；② 真机烧录后串口/日志看到任务全部创建成功 + 关键外设握手成功；③ 记录堆余量实测值；④ 明确列出"依赖外部数据链路（未上电前无法验证的部分）"。缺任何一项 = 只能说"代码层面已就绪"，不得声称"上电即跑"。
